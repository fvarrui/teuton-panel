# Results dashboard

## Goal

A teacher page, suitable for the classroom projector, with the latest results of every case.

## Context

- The reference classroom projects the results table next to a registered-students page (`docs/history.md`).
- Teuton writes `var/<test>/resume.json` (grade, members, `conn_status`, `moodle_id`) and `case-NN.json` (per-target detail).
- Teuton panel v1 (Java) had Cases, Resume and Hall of Fame tabs; a useful checklist.

## Changes

- Teacher page `/teacher/results`, fed by the results store (latest result per student, whichever run produced it): members, grade, connection status, time of that result; registered students never evaluated appear as "pending", disabled ones as "disabled" (with their last result, if any).
- Highlight connection problems (`conn_status`), low grades and `unique_fault` (grade 0 for copying, with the reason).
- Case detail page: per-group targets with check result, command, expected and output. Never show the report's `config` or any password; projector mode hides commands and output too.
- Hall of fame / grade distribution.
- Auto-refresh (small inline JS polling `/teacher/results.json`, or a meta refresh); a large-font projector mode, which also shows the student URLs (see `panel-config`).
- Download `moodle.csv` generated by the panel from the store (`MoodleID, TeutonGrade, TeutonFeedback`, as Teuton does), so it includes students evaluated in partial runs.
- Empty state when nothing has run yet.

## Acceptance

- After a run, the dashboard shows every case's grade within the refresh interval, without reloading by hand.
- An unreachable student machine is visible as a connection problem, not just grade 0.
- Opening a case shows the result of each target and no password.
- A student evaluated alone keeps everyone else's results on the dashboard.
